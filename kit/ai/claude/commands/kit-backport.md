1. อ่าน `knowledge/lessons-learned.md` หัวข้อ "2. บทเรียนของงานนี้ (/lesson)" (L# ที่ระบุว่า generic / ใช้ได้ทุกงาน) และ `status/MIGRATION_STATUS.md` หัวข้อ "Kit — สิ่งที่แก้/เพิ่ม" (K#)
2. แยกเป็นตาราง: | รหัส | ชนิด (บทเรียน / สคริปต์ / คำสั่ง) | ใช้ได้ทุกงาน? | หลักฐาน | ความเสี่ยง (ข้อมูลลูกค้า / ชื่อระบบภายใน) | — เฉพาะงานนี้ = ไม่ส่ง
3. **บทเรียน (L#)** ที่ใช้ได้ทุกงาน → สร้างแผน (ยังไม่เขียนอะไร):
   `python ../../../../tools/workspace.py kit-promote --job {{PROJECT}}/{{JOB}} --lesson L<เลข> [--lesson …]` → exit 3 = รอคนอนุมัติ · exit 1 = มีข้อที่ต้องแก้ก่อน (ไม่มีหลักฐาน / ไม่ได้ระบุ generic / promote แล้ว)
4. ❓ ยกข้อความของแผนมาแสดงในแชท แล้วถามผู้อนุมัติ (ชื่ออยู่ใน `shared/approvers.json` → `knowledge_approvers`):
   `1 = อนุมัติ` · `2 = แก้ข้อความก่อน (แก้ในงานแล้วสร้างแผนใหม่)` · `3 = ไม่ส่ง` — ตอบเป็นเลข · **ห้ามเลือกแทนคน ห้ามใส่ชื่อผู้อนุมัติเอง ห้ามแก้บทเรียนหลังได้รับอนุมัติ**
   ตอบ 1 → ให้คนพิมพ์ชื่อ + วันที่ แล้วรัน `kit-promote … --plan-id <id จากแผน> --approved "<ชื่อที่คนพิมพ์> <YYYY-MM-DD>"` (plan id ไม่ตรง = เนื้อหาเปลี่ยน ต้องดูแผนใหม่)
5. ผล: แถว LT# ใน `../../../../shared/knowledge/lessons-learned.md` + ledger `PROMOTIONS.json` — ทุกงานเห็นทันทีผ่าน `/wiki` · ห้ามแก้ / ลบไฟล์ทั้งสองเอง
6. **การแก้สคริปต์ / คำสั่ง (K#)** → ไม่ patch ในงาน · สรุปให้คน (ไฟล์ · อาการ · หลักฐาน · ข้อเสนอ) เพื่อส่งผู้ดูแล kit แก้ใน `kit/` แล้วออก kit รุ่นใหม่ (`docs/TEAM_WORKFLOW.md`) · งานเดิมยังใช้รุ่นที่ล็อกไว้
